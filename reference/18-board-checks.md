# Checks worth running on a board

Statements where the public drivers disagree, where only one driver shows the fact, or where the fact is inferred, and which a Pico W / Pico 2 W running embassy's driver could settle by reading. No check needs a join, an active scan, a transmitted frame or a look inside the firmware image.

## Conventions

- "Expected" is what each driver's source implies the board will show. It is the driver's view, not a statement about the chip. None of these observations is recorded in these sources; the tables list predictions only.
- Most rows need a test build of embassy that logs raw bytes (SDPCM headers, reply lengths, register values) or issues one extra get. That is host-side logging; the bytes sent to the chip are a get the drivers already send, unless the Risk column says otherwise.
- "Passive scan" means embassy's `ScanType::Passive`, which its source describes as listening for beacons without sending probes `embassy/control.rs:48-50`. Rows 5, 7, 13, 14 and 31 start one; skip them if starting a passive scan does not count as read-only.
- Risk "none" means reads, counts or timing only. Risk "changes a setting" means one write the stock embassy bring-up does not make. No row needs a second device.
